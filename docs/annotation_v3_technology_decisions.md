# Annotation v3 technology decisions — 2026-11-06

Official repository metadata and ambiguous LICENSE files were fetched on this date. Raw research is in ignored `data/annotation-v3-runs/audit/`. No candidate source code was copied. No Python/Node package, model, CUDA/driver or lockfile was changed for v3. Estimated installation impacts below are qualitative; repository size is **not** installation/download size. Model-weight licenses require separate checks from library licenses if ever adopted.

| Official source | Actual function / license checked | Fit, cost/resource/integration | Decision |
|---|---|---|---|
| [MCP Apps ext-apps](https://github.com/modelcontextprotocol/ext-apps) | Embedded MCP app UI/spec SDK; license is transitioning MIT→Apache-2.0, documentation CC-BY-4.0, legacy contributions may remain MIT | MCP UI/runtime adds integration surface; no annotation grounding engine; CPU/Node, no GPU itself | Interface concept only. Internal tools first; no MCP server installed |
| [pdf-mcp](https://github.com/sandraschi/pdf-mcp) | PDF tools, validation, workbench/RAG; MIT | Additional server/DB/frontend overlaps current product; CPU RAM and dependency expansion | Tool-boundary reference only; no copy/install |
| [PyMuPDF](https://github.com/pymupdf/PyMuPDF) | Native PDF extraction, vector export, raster previews; AGPL-3.0 (existing dependency) | Existing coordinate/render path, incremental CPU/RAM only | Reuse existing engine. Deployment must satisfy its existing AGPL/commercial licensing terms; not a new permissive-library adoption |
| [Qwen3-VL](https://github.com/QwenLM/Qwen3-VL) | Multimodal inference; repo Apache-2.0 | Existing 8B NF4 SSD cache and isolated GPU worker; budget/VRAM constraints measured, no weight download | Reuse for visual plan/review; no larger model |
| [SoM](https://github.com/microsoft/SoM) | Set-of-Mark visual prompting; MIT | Existing stable element overlay, no new model/runtime | Reuse current local implementation, no copied source |
| [Docling](https://github.com/docling-project/docling) | Structured document conversion; MIT library | New OCR/layout/model dependencies and RAM, possible GPU contention; scanned math needs concrete corpus first | Deferred. Native glyph graph addresses current vector-PDF case |
| [MinerU](https://github.com/opendatalab/MinerU) | Document parsing; current LICENSE is Apache-2.0 **plus additional commercial thresholds and online-service attribution** | Large model/runtime integration, GPU/RAM/cache duplication | Deferred; not described as plain Apache/AGPL. No code/weights copied |
| [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) | OCR/document structure; Apache-2.0 library | Additional inference framework/models, conflicting GPU lifecycle risk | Deferred pending image-PDF precision fixtures |
| [SAM 2](https://github.com/facebookresearch/sam2) | Image/video segmentation; Apache-2.0 | Extra GPU weights/runtime; segments regions but cannot infer mathematical point/vector meaning | Deferred. Conservative simple-plot pixel candidates + VLM confirmation only |
| [Rough.js](https://github.com/rough-stuff/rough) | Sketchy vector primitives; MIT | Browser package; PDF path parity would require adapter | Existing seeded Natural Ink retained; no extra dependency |
| [perfect-freehand](https://github.com/steveruizok/perfect-freehand) | Pressure-sensitive stroke outlines; MIT | Adds outline tessellation/preview-export parity work; CPU | Deferred; current pen strokes do not have observed pressure data |
| [OR-Tools](https://github.com/google/or-tools) | Constraint/optimization solvers; Apache-2.0 | Additional binary CPU package/RAM, objective tuning; no GPU needed | Deferred. Keep existing tested heuristic/routing, measure failures first |
| [elkjs](https://github.com/kieler/elkjs) | Graph layout algorithms; EPL-2.0 verified LICENSE | Node graph layouts do not directly encode PDF occlusion/glyph constraints | Deferred; coordinate/path executor already exists |
| [Excalidraw](https://github.com/excalidraw/excalidraw) | Whiteboard UI and connectors; MIT | Full editor/build/storage integration unrelated to current upload/review workflow | Reference only; no editor rewrite |
| [promptfoo](https://github.com/promptfoo/promptfoo) | Prompt/agent evaluation framework; MIT repo | Extra Node tool/provider harness; paid/GPU evaluator cost needs explicit corpus | Deferred; current pytest + A/B/C artifact harness reused |
| [lecture-to-notes](https://github.com/drpwchen/lecture-to-notes) | Grounded lecture notes and timestamp-synced viewer; MIT | Parallel end-to-end pipeline would duplicate STT/alignment/notes/cache | UX/provenance reference only; current source/audio chain retained |
| [LectureLens](https://github.com/r0mar1n/LectureLens) | Lecture video→multimodal notes | Repository has no recognized license and `/license` returned 404; multi-model pipeline costs unmeasured | No code reuse/install. Behavioral ideas only until rights clarified |

New functionality is local Python code using existing Pydantic, PyMuPDF and NumPy; semantic calls use the existing configured provider. Native glyph/subexpression extraction adds CPU geometry work, not another OCR/VLM model. Figure pixel candidates are specialized heuristics and explicitly remain unverified semantic candidates until supported visual confirmation. This is not general chart understanding.
